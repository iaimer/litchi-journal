# 玻璃界面真机反馈修正计划

日期：2026-10-04。状态：实现、代码审查与模拟器验证完成，正常入口 Release 测试包已构建；ColorOS 真机最终验收待用户。

## 目标与边界

修复冷启动、点击今天和展开扇形菜单时加号异常缩放；今天、过往、习惯使用完全相同的 Dock 宽度和位置；记录加号移到 Dock 上方右侧；顶部在内容经过背后时产生真实背景模糊。

保留暖纸底色、Today Rainbow、Lucide 图标、阅读排版、来源返回动效和既有业务。只修改 Flutter 展示层，不修改 API、服务端、Parser、Markdown、领域模型和真实 Vault。不新增过往或习惯页记录入口，不迁移配置。本计划不代表已完成验收；正式发布和版本号另行处理。

## 已确认的原因

### 加号与整个扇形菜单弹跳

`lib/screens/home_screen.dart` 每次构建都创建新的 `FloraDockFabLocation`；`lib/widgets/flora_dock.dart` 的该类没有按定位值实现相等比较。Flutter 的 Scaffold 因定位对象不相等而启动默认 FAB 移动动画，即使起点和终点完全相同也会缩小后恢复。动画包住整个扇形宿主，因此加号发生位移，扇形也一起缩放。

冷启动后的配置、日记加载更新，点击今天时 `lib/main.dart` 的重新构建，以及菜单切换都可以触发这条路径。仅阻止重复点击今天不能解决冷启动和菜单弹跳。

已使用临时响应、真实 `MainScreen` 进行逐帧复现，没有访问真实服务或 Vault：冷启动、重复点击今天、从过往返回今天、展开菜单四个场景均复现。56dp 加号最小缩到约 1.4dp，随后恢复。独立对照中，仅保持定位对象稳定，或仅使用 SDK 的 `FloatingActionButtonAnimator.noAnimation`，均让按钮保持 56dp。这不是 ColorOS 特有的系统弹性效果，也不是已设计的径向菜单动效。

之前 639 项回归通过不等于不存在这个问题：现有检查主要覆盖结束位置和遮挡，没有覆盖 Scaffold 外层变换的每一帧。

### 今天与其他页面的 Dock 不一致

`lib/main.dart` 只在今天的 Dock 右侧保留 68dp，用来并排容纳加号。切换页面时 Dock 自身宽度就会变化；这属于之前的布局决策，需要按本次反馈替换，不是调整透明度能解决的。

### 顶部与 Dock 玻璃较弱

`lib/widgets/flora_app_bar.dart` 只给操作按钮包玻璃，AppBar 本身仍为普通不透明表面。首页列表位于 AppBar 下方；过往和习惯的标题位于列表外部的 Column 顶部，内容不经过标题背后。模糊均匀底色没有可见细节，增大模糊值也不会产生参考图的效果。

Dock 已使用实际 `BackdropFilter`，但 `lib/theme/app_theme.dart` 中浅色填充不透明度为 0.78、深色为 0.82，且暖色填充与页面接近，因此底层内容只留下较弱轮廓。顶部结构问题已由代码确认；最终玻璃强度与 GPU 表现仍需真实设备验证。

## 第一批：消除额外 FAB 动画

### 修改 `lib/widgets/flora_dock.dart`

1. 为 `FloraDockFabLocation` 添加基于 `bottom` 的值相等和 `hashCode`，保留构造参数与现有定位算法。
2. 增加简短注释，说明相同定位值必须避免 Scaffold 将重建误判成位置变更。
3. 不修改扇形内部的动画控制器，不引入新的全局动画控制器。

### 修改 `lib/screens/home_screen.dart`

1. 在承载扇形的 Scaffold 显式使用 `FloatingActionButtonAnimator.noAnimation`，只关闭框架额外的整组缩放与位移动画。
2. 保留 `QuickRecordFan` 自己的展开 220ms、收回 160ms、连续反转、子按钮淡入与缩放，以及加号旋转。
3. 验证初次加载、日记刷新、标签配置更新、菜单状态变化均不再影响主按钮位置和大小。

### 修改 `lib/main.dart`

1. 点击已选中的今天或过往时直接返回，不触发无意义的页面重建。
2. 不把此优化当作根本修复；仍通过冷启动、数据更新和菜单切换测试。
3. 保留习惯页现有刷新语义。若重复点击习惯目前用于刷新，继续保留；进入习惯仍更新原刷新令牌。

### 新增 `test/glass_navigation_regression_test.dart`

1. 将临时复现迁入正式测试，使用真实 `MainScreen` 和受控 HTTP 响应。
2. 从首个可绘制帧开始，每 16ms 采样主加号实际绘制矩形，至少覆盖 500ms。
3. 覆盖冷启动、重复点击今天、过往与习惯返回今天、日记异步加载完成、菜单展开与收回、连续反转。
4. 在没有屏幕尺寸或安全区变化的前提下，主按钮宽高始终为 56dp，位置变化不超过 0.5dp；不得只断言动画结束后的矩形。
5. 同时检查扇形宿主的尺寸稳定，子按钮仍按原来的极坐标路径运动，没有叠加整组缩放。
6. 检查关闭时立即撤销点击、焦点和语义，以及减少动态效果时直接完成等现有行为。

## 第二批：把记录入口移到 Dock 上方

### 修改 `lib/main.dart` 和 `lib/widgets/flora_dock.dart`

1. 删除仅今天存在的 68dp 右侧占位。
2. 三个页面的 Dock 均使用左右 16dp、底部 8dp 加系统安全区的相同布局，始终完整居中。
3. 今天加号位于 Dock 上方右侧，按钮底部与 Dock 顶部先采用 12dp 间距，右侧仍为 16dp。
4. 将 `fabBottom` 的计算集中为 `systemBottom + 8 + dockHeight + 12`，不要在子页面重复推算安全区。
5. 检查阅读内容末尾的可滚动留白；既要能滚出 Dock，也要能滚出右侧加号遮挡范围。不要通过收窄所有正文来避让。

### 修改 `lib/widgets/quick_record_fan.dart`

1. 去除“加号与 Dock 并排”才需要的角度或半径限制，按移高后的实际可用区域重新验证极坐标布局。
2. 保持展开前后相同的宿主尺寸；主加号只旋转，不平移或缩放。
3. 子入口仍使用至少 48dp 热区，不能碰 Dock、屏幕边缘或互相重叠。
4. 保留四个今天入口与三个历史补录入口，不恢复已移入记录页的独立照片入口。
5. 记录页返回动画继续收回实际主加号，不错误返回 Dock；历史补录无主 Dock，保留原有独立定位。

### 更新测试

1. 修改 `test/glass_origin_motion_test.dart` 中旧的并排布局断言，改为加号在 Dock 上方且至少相隔 12dp。
2. 在导航回归测试比较三个页面 Dock 的完整矩形，位置和宽度一致。
3. 检查 320dp、1.3 倍字体、不同底部安全区下，加号、四个子入口和 Dock 均在可见区域内。
4. 保留来源返回、热区、菜单点击、标签对齐和时间轴布局测试，不放宽已有业务断言。

## 第三批：让顶部真正成为背景玻璃

### 修改 `lib/widgets/flora_glass.dart` 和 `lib/theme/app_theme.dart`

1. 复用现有局部裁剪与 `BackdropFilter`；增加顶部全宽背景表面，不给标题再套一张圆角卡片。
2. 标题和按钮在模糊层上方清晰绘制，只模糊背后内容，不能模糊前景文字。
3. 将顶部、Dock 与菜单的填充职责分开。顶部与 Dock 可从浅色约 0.42、深色约 0.60 开始对照调试，这只是起始值，不作为未经验收的最终标准。
4. 菜单和对话框继续优先保证可读性，不为了强化 Dock 而一起降低全部浮层的不透明度。
5. 使用克制的亮边与阴影表达边缘，避免厚重白框、强反光或额外装饰。背景本来为空时允许玻璃安静，不伪造纹理。
6. 高对比度模式继续使用不透明表面；模糊仅限顶部、Dock 和已有局部浮层，不增加全屏模糊或复杂折射依赖。

### 修改 `lib/widgets/flora_app_bar.dart`

1. 为需要内容穿过背后的阅读页提供明确的玻璃背景模式，保留原公开参数和路由语义。
2. 玻璃背景覆盖标题带与状态栏安全区；AppBar 自身不得用不透明色再次盖住背景。
3. 已有按钮玻璃避免与整条顶部玻璃重复叠加，造成双重模糊或过白。
4. 黑色沉浸式图片预览保持黑色遮罩，不套用暖纸顶部规则。不要仅修改公共 AppBar 就默认所有页面完成适配。

### 修改 `lib/screens/home_screen.dart` 与 `lib/screens/read_only_diary_screen.dart`

1. 让滚动正文能够经过透明顶部之后；使用 `extendBodyBehindAppBar` 时同步补足实际 AppBar 高度和顶部安全区。
2. 初始正文位置保持清楚，滚动后内容从标题背后经过，而不是被截断在标题下方。
3. 调整下拉刷新指示器的起点，确保不会藏在玻璃标题后面。
4. 保留首页日期、历史年份、副标题、设置按钮与补录行为。

### 修改 `lib/screens/past_screen.dart`

1. 将“标题在 Column 外、图墙单独滚动”的结构改为同一滚动体系内的置顶头部与画廊。
2. 优先使用当前 Flutter SDK 已提供的 `PinnedHeaderSliver`，让标题、月份和展开日历根据真实内容自然计算高度，不手写固定高度，不引入第三方依赖。
3. 保留月份选择、日历展开收回、分页、月份定位及原滚动控制器；检查迁移后的月份偏移计算。
4. 验证头部绘制顺序：背景采样必须确实包含滚到其后的图墙。若现有视口绘制与裁剪阻断采样，再采用独立顶部覆盖层，并以真实头部布局高度保留初始空间，不凭猜测增加空白。
5. 日历展开时不压坏图墙或引发标题跳动，关闭后恢复原可用空间。

### 修改 `lib/screens/habit_stats_screen.dart`

1. 将标题与统计列表纳入相同的滚动体系，标题置顶，指标与热力图可以经过其背后。
2. 使用与过往相同的顶部玻璃与安全区规则；周期控件、统计模块和热力图业务不变。
3. 刷新仍保留已有内容；页面空白或首次占位时不通过假图案制造模糊。

### 新增 `test/glass_header_test.dart`

1. 用受控彩色图块和文字滚过顶部，检查内容的实际绘制位置进入顶部背后，而非只查找一个 `BackdropFilter`。
2. 通过真实渲染截图或像素采样确认背景细节被柔化、颜色仍可透出，标题和操作图标保持清晰。
3. 对照同一背景的未模糊版本，排除仅降低透明度而没有背景模糊的假通过。
4. 覆盖浅色、深色、高对比度、320dp 与 1.3 倍字体，标题和按钮不裁切，日历展开高度自然增长。
5. 检查刷新、月份跳转、页内滚动位置保留与顶部操作热区，不以截图替代这些交互测试。
